# 文案提取工具 · 平台账号与网络出口申请说明

> 用途：向公司申报"抖音等平台账号"与"国内代理节点"的支持。
> **结论先行**：账号解决"能不能以正常用户身份看到内容"，代理解决"多个账号是不是看起来像不同的人"。
> 两者到位后，本工具可从"偶尔用用"变成"每天稳定出稿"。**请按下面的目标量级准备资源**。

---

## 一、目标量级与资源诉求（核心表）

按"每条视频平均 3 分钟"折算；抖音是主力平台，占比最大。

| 目标量级（条/天） | 抖音账号 | 小红书账号 | 快手 | **代理节点** | 机器/算力 |
|---|---|---|---|---|---|
| **500 条/天** | **10~12 个** | 2~3 个 | 匿名（靠 IP 池） | **16~20 条** | 现有单机可支撑 |
| **1000 条/天**（建议按这个申报） | **20~25 个** | 4~5 个 | 匿名（靠 IP 池） | **32~40 条** | 现有单机吃紧，**建议第二台** |
| **2000 条/天** | **40~50 个** | 8~10 个 | 匿名（靠 IP 池） | **70~80 条** | **必须 2~3 台机器** |

**换算口径（便于对方核验）**
- 单账号安全日量：抖音 **30 条/天**（上限 50，留冗余按 30 算）
- 账号数 = 目标日量 ÷ 30 × 1.2（冗余系数，用于轮换与故障替换）
- 代理数 ≈ 账号数（**一号一 IP** 最稳；快手无账号概念，按"每 IP 40 条/天"分摊）

> 快手为什么也要代理：它虽然**不需要账号**，但风控看 IP。没有代理时，快手的请求全部从公司
> 同一条 IP 出去，量一大就整条 IP 被限流——账号池救不了它。

## 二、为什么需要平台账号

平台对"未登录的高频访问"判定非常敏感。账号的作用是让请求**以一个正常用户身份**发生：

| 平台 | 是否需要账号 | 原因 |
|---|---|---|
| **抖音** | **需要（跑量的核心）** | 公开视频匿名能看，但高频会被判机器；多账号才能把每天的请求摊开、个别号被限流不影响整体 |
| **小红书** | **需要（技术刚需）** | 多数笔记必须登录态才能查看，没有账号 = 大部分内容取不到 |
| **快手** | 不需要账号 | 分享页无需登录即可读取（但需要 IP 分散，见第一节） |
| **B站** | 基本不需要 | 公开视频匿名可读，仅大会员内容需要 |
| **视频号** | 不需要 | 走本地导出文件，与账号无关 |

**账号规格要求**：专用小号，**不要用公司主号/对外号**；能提供现成的登录 cookie（Netscape 格式）
或账号密码即可，工具侧已支持批量导入与自动轮换。

## 三、为什么需要代理（国内节点）

**没有代理时**：所有账号都从公司同一条出口 IP 访问平台——平台侧看到的是"同一扇门后面换了几张脸"，
把多个账号关联起来的成本极低，**账号再多也打折**；而且这条 IP 一旦被限流，所有账号一起停。

**有代理之后**：一个账号固定走一条 IP，每个账号在平台看来是"不同的机器、不同的网络"，
账号的价值才真正成立；某条 IP 出问题也只影响对应账号。

**明确边界**：代理只用于**分散出口**，不用于绕过地域限制、不访问境外内容、不隐藏违规行为。

| 项 | 要求 |
|---|---|
| 数量 | 见第一节（按量级） |
| 出口位置 | **中国大陆**，尽量固定同一城市（同一账号始终同一城市） |
| 认证方式 | **优先"IP 白名单"**（把公司出口 IP 报备给服务商）；若只能账号密码认证，工具侧需额外改造（已评估，可做） |
| 类型 | **短效住宅 IP 优先**；机房 IP 已被平台标记，效果差 |
| 协议 | 支持 HTTP 或 SOCKS5 |
| 计费 | 按 IP 计费更省心；若按流量，见下方估算 |

**代理流量估算**（工具已配置为**只有页面/接口走代理，视频音频直连**）

| 量级 | 页面流量 | 月流量（30 天） | 建议购买 |
|---|---|---|---|
| 500 条/天 | ~0.5GB/天 | ~15GB | 20GB/月 |
| 1000 条/天 | ~1GB/天 | ~30GB | **50GB/月** |
| 2000 条/天 | ~2GB/天 | ~60GB | 100GB/月 |

> 注意：**媒体（视频/音频）不要走代理**。一条 3 分钟视频原片 20~60MB，若走代理，1000 条/天
> 就是 30~60GB/天，流量费会失控。工具默认已按"媒体直连"配置。

## 四、算力与磁盘（容易漏掉的两个瓶颈）

**算力（关键约束）**：语音转写跑在本机 GPU 上，实测速度约 **4.5 倍实时**（1 分钟视频约 13 秒）。
按此折算：

| 量级 | 需要的转写时间/天 | 单机是否够 |
|---|---|---|
| 500 条/天 × 平均 3 分钟 | 1500 分钟视频 ÷ 4.5 ≈ **5.6 小时** | ✅ 够（还有余量做 OCR、笔记、重试） |
| 1000 条/天 × 平均 3 分钟 | 3000 分钟 ÷ 4.5 ≈ **11 小时** | ⚠️ 接近满载，建议第二台机器或开批处理推理 |
| 1000 条/天 × 平均 10 分钟（长视频多） | 10000 分钟 ÷ 4.5 ≈ **37 小时** | ❌ **单机不可能**，必须第二台 |

→ 结论：**短视频为主时，瓶颈是账号与 IP；长视频（视频号那类）占比高时，瓶颈是算力。**

**磁盘**：

| 项 | 估算 | 建议 |
|---|---|---|
| 原始视频（若要留档） | 40MB/条 × 1000 条 = **40GB/天** | 只保留最近 3~7 天（120~280GB），或"转写完成即删原片" |
| 音频 + 文案 + 归档 | 约 3MB/条 → 3GB/天 | 长期保留，成本低 |
| 建议配置 | — | 系统盘之外单独一块 **1TB 以上的数据盘** |

**网络带宽**：媒体直连下载 40GB/天 ≈ 平均 3.8Mbps，普通办公线路够用（峰值会短时更高）。

## 五、不提供会怎样（用于说明必要性）

| 缺什么 | 后果 |
|---|---|
| **账号不足** | 抖音只能以远低于目标的频率匿名运行；一旦被限流没有备用身份，任务成批失败 |
| **代理不足** | 多账号共用一条 IP，平台关联成本极低；该 IP 被限流时所有账号一起停；**账号数量越多，边际收益越低** |
| **算力不足** | 任务排队积压，出稿延迟以小时计（长视频场景尤其明显） |
| **磁盘不足** | 原片堆积到几十~上百 GB，需要人工清理 |

## 六、合规与使用边界（申报时通常最关心）

1. **只提取公开内容**：不访问需要特殊权限的内容，不做批量爬取，不绕过任何访问控制。
2. **账号仅用于"以正常用户身份访问"**：不代刷、不互动、不改动平台数据、不用于商业转售。
3. **控制频率**：工具内置按平台的请求节奏（最小间隔 + 随机抖动）、按平台的每日总量上限、
   **按账号的每日上限**、被限流时自动停手冷却——**不追求"越快越好"，追求"长期不打扰平台"**。
4. **凭证集中保管**：账号凭证保存在本机 `cookies/` 目录，**不入版本库、不外发**；停用时统一删除。
5. **数据用途**：仅作公司内部素材整理与选题参考，不对外发布原片、不做二次分发。
6. **遵守**：平台服务条款及《网络安全法》《数据安全法》相关要求。

## 七、技术侧已就绪的部分（拿到账号/代理即可用）

- **账号池**：多账号自动轮换（跳过被限流的号、按"今日用量最少 + 成功率高"挑选）
- **账号级日上限与健康度**：每个号跑多少、成功率多少，页面可见
- **一号一身份**：每个账号独立浏览器指纹目录，登录态互不串
- **出口池与绑定**：一个账号固定走一条 IP；出口出问题只影响对应账号
- **登录与抓取同出口**：避免"登录在一个地方、抓取在另一个地方"这种异常信号
- **自动告警**：失败率异常、队列积压、磁盘不足、出口不通都会主动提示

## 八、申请清单（按 1000 条/天 目标）

> 请协助提供：
> 1. **抖音账号 20~25 个**（专用小号，仅用于文案提取，不做互动/发布）
> 2. **小红书账号 4~5 个**
> 3. **国内代理节点 32~40 条**（大陆出口、优先支持 IP 白名单认证、短效住宅 IP 优先、HTTP/SOCKS5）
> 4. **一台可常开的机器**（现有机器可跑 500 条/天；1000 条/天建议增配第二台，或升级 GPU）
> 5. **一块 1TB 以上数据盘**（存放原片与归档；原片按 3~7 天滚动清理）

> 若目标量级不是 1000 条/天，按第一节表格等比增减即可。

---

**一句话总结**：账号决定"每天能跑多少条"，代理决定"这些账号能不能同时用"，
算力决定"跑得完跑不完"。三者按目标量级配齐，这套工具才能稳定承担日常出稿任务。
