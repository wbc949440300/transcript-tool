## 二、按场景的最小资源

| 场景 | 账号 | 代理 | 说明 |
|---|---|---|---|
| 给链接就出文案（抖音/B站/快手） | 0 | 0 | 现在就是这样跑的 |
| 加「按关键词自动找视频」 | 抖音 1~2 个 | 0 | 只用搜索，不用它跑量 |
| 加「小红书笔记」 | 小红书 1~2 个 | 0 | 登录态刚需 |
| 日量超过 200 条，或出口开始被连续拦 | 不变 | 先 1 条试 | 见第五节触发条件 |

**为什么不再按「1000 ÷ 30 = 34 个号」推算**：那个口径的前提是「每一条提取都要消耗账号额度」。实测下来前提不成立——匿名就能取详情、图集、评论、分享链接，只有搜索这一件事需要登录，而搜索是「找链接」的一次性动作，不是「每条提取」的持续消耗。

## 四、代理：什么时候买、买什么

**触发条件（三条同时满足才买）**：
1. 连续 3 天成功率低于 80%；
2. 日志出现连续的「验证码中间页」，而不是偶发；
3. 换过干净上下文/换过一条出口仍然被拦。

**买什么**：

| 项 | 要求 | 原因 |
|---|---|---|
| 类型 | **静态住宅**（或超长会话粘性），不用轮换型 | 轮换型会让「一号一 IP 绑定」与「按线路隔离故障」同时失效，且账号出口频繁跳动本身是异常特征 |
| 出口位置 | 中国大陆 | 海外/机房 IP 访问目标平台反而更容易被识别 |
| 数量 | 从 1 条试起 | 判据通过才补，避免一次性投入 |
| 流量 | 只让页面/接口走代理，媒体直连 | 一条 3 分钟原片 20~60 MB，媒体走代理流量费会失控（工具默认已按媒体直连配置） |

## 六、合规与使用边界（申报时最关心）

1. **只提取公开内容**：不访问需要特殊权限的内容，不绕过访问控制；确实需要登录态时才使用自己的账号。
2. **账号仅用于「以正常用户身份访问」**：不代刷、不互动、不改动平台数据、不用于转售。
3. **控制频率**：内置按平台的请求节奏（默认同域名 ≥2 秒 + 0~50% 抖动）、平台级串行、每日总量上限、被限流自动冷却——不追求快，追求长期不打扰平台。
4. **凭证集中保管**：cookie 保存在本机 `cookies/`，不入版本库、不外发；停用统一删除。
5. **数据用途**：仅作内部素材整理与选题参考，不对外发布原片、不做二次分发。
6. **遵守**：平台服务条款及《网络安全法》《数据安全法》相关要求。

## 七、技术侧已就绪（拿到资源即可用）

- **匿名通道**：默认 `TRANSCRIPT_COOKIE_MODE=fallback`（匿名优先），只有判定「缺登录态」才带 cookie；
- **账号池**：多账号 + 独立浏览器指纹目录 + 账号级日上限与健康度；
- **出口池**：一个账号固定走一条 IP，出口故障只影响对应账号；`cookies/.cooldown.json` 记录冷却，重启仍生效；
- **节流与冷却**：平台串行 + 域名节流 + 失败分级（profile 被标记 vs 出口被限不混为一谈）。

---

**一句话总结**：现在决定「每天能跑多少条」的是**转写算力**，不是账号，也不是代理；
账号只决定「能不能按关键词搜」，「能不能看小红书」。
