# 画面文字 OCR：修复 + 默认开启（2026-10-31）

> 起因：用户反馈视频截图里的文字是"肥水不流外人田"，工具提取到的却是
> "非说也没有留到外人天地里去"。结论：**画面里的硬字幕比 ASR 准**，应当优先利用。

---

## 1. 修掉的两个真 bug

### 1.1 抖音/快手勾了"识别画面文字"根本不执行

`_run_task` 里抖音/快手是**专用通道提前 return** 的，而画面文字 OCR 那段代码挂在
**通用通道后面** → 两个主力平台永远不执行。

修复：
- 抽出 `_run_frame_ocr(task, work_url, work_dir)`，三条收尾路径（抖音/快手/通用）都调用
- 视频源优先级：本地 `video.mp4` → 任务目录里的媒体 → 任务直链（`http` / `file://`）
- `_mark_success()` 补上 `frameText`（旧实现只走通用路径，漏了专用通道的持久化字段）

### 1.2 本地文件也带 `-headers` → 抽帧整条失败

```
WARNING [frame_ocr] 抽帧失败: Option headers not found.
Error opening input file tasks\<id>\audio_1793422146590.mp4
```

`-headers` 是 HTTP 协议专用输入选项，对**本地文件** ffmpeg 直接报错。这个坑旧代码就有，
只是因为旧路径多数时候走的是 http 直链，没人注意。

修复：`_frame_cmd()` 只对 `http(s)` 源加 `-headers`（本地文件永远不需要 Referer）。

## 2. 两个优化

| 优化 | 原因 | 做法 |
|---|---|---|
| **采样覆盖整条视频** | 旧公式把间隔封顶在 5 秒，长视频只采到前 48×5 = 4 分钟，后面字幕全丢 | `interval = max(1.5, 总时长/最大帧数)`，不再封顶 |
| **抽帧缩到 720 宽** | 1080×1920 每帧 OCR 约 6 秒（4:13 视频花了 4 分 46 秒） | `scale=720:-2`（字幕照样清楚），归一化坐标按缩放后的尺寸算 |

## 3. 默认开启（用户要求的"字幕优先"第一步）

| 位置 | 变化 |
|---|---|
| `PlatformAdapter.frame_ocr_default` | 抖音 / 快手 / 小红书 = True（没有平台字幕文件）；B站 / TikTok = False（可能有 CC） |
| `CreateTaskRequest.ocrFrames` | 改成**三态**：`null`（未指定）→ 按平台决定；`true/false` → 调用方说了算 |
| `POST /transcript/doTask` | 未指定时用 `frame_ocr_default_for(url)` |
| 批量创建 | 同样按平台默认 |
| 前端视频页 | 粘贴链接后**自动按平台勾选**「识别画面文字」；用户手动改过之后不再覆盖他的选择 |

## 4. 实测

真实抖音视频（4:13，3D 动画带大量标注），**不传 `ocrFrames`**（走平台默认）：

```
口播（ASR）       1164 字
画面文字（OCR）   1178 字   ← 48 帧 → 98 条，丢弃水印 0
```

即：抖音任务现在**自动**同时产出两条文本，画面里的标注/字幕不会漏。

代价（优化前后）：

| | 优化前 | 优化后 |
|---|---|---|
| `-headers` | 本地文件直接失败 | 正常抽帧 |
| OCR 阶段耗时（48 帧） | **4 分 46 秒** | 复测中（缩小 + 缩放后应显著下降） |
| 采样覆盖 | 只到第 4 分钟 | 整条视频 |

## 5. 测试

`pytest`：**145 项全过**。新增 12 项：
- 抖音/快手通道必须执行 OCR；显式关闭时跳过
- `_run_frame_ocr` 取源与写回 `frameText`
- 本地源不加 `-headers`、http 源加 Referer
- 抽帧缩放参数
- 采样间隔覆盖整条视频（10 分钟视频 → 12.5 秒/帧）
- 按平台的默认开关；API 三态（不传/true/false）

## 6. 第 3 步：画面字幕优先（已完成）

### 6.1 画面字幕参与纠错（治"整句听错"）

- `correct_transcript(..., subtitle=)`：把画面字幕作为「参考」写进提示词，并明确允许
  **较长的替换对**（把听错的整段换成字幕里的写法）
- **本地校验**：目标写法必须能在字幕文本里找到（`b in subtitle`）才放行，长度上限 60 字、
  长度差上限 30 字；否则走原来的严格规则。字幕只是"证据"，不是"指令"
- `applied` 里的条目带 `kind: "subtitle"`，前端改动清单能看出哪些是靠字幕改的
- API 侧自动接线：`/ai/correct` 从历史记录里取 `extra.frameText` 当参考，无需额外参数

实测（真实抖音弹道视频，1164 字口播 + 1145 字画面字幕）：

```
耗时 9.2s | 5 块 | 32 处改动 | 其中字幕对齐 20 处
起劲压力 → 膛压          使他弹线 → 使得膛线       原柱布 → 圆柱部
而且美发子弹的分离位置并不一致 → 而且每发子弹的分离位置并不一致   ← 整句级修正
使弹琢点更加分散 → 使弹着点更加分散                 尾锥脚 → 尾锥角
```

### 6.2 没有口播时，画面字幕就是正文

- `_run_frame_ocr` 里判断：口播（ASR）短于 15 字 → 认为"没有有效口播"，
  把画面字幕设成 `textContent`（原口播保留在 `sourceText`）
- 场景：纯音乐视频、告示牌视频——以前只拿到一句"没有识别到口播"的提示，现在能直接出文案
- `frameBlocks`（带时间戳的画面文字块）也一并入库，为后续"按时间对齐 ASR/字幕"留数据

## 7. 性能（两段式探针 + 实测）

### 7.1 两段式（2026-10-31 提速）

```
第 1 段 探针：只抽 8 帧（按整条视频均分，覆盖率不缩水）
  ├─ 没有"正文类文字" → 直接返回，不再跑全扫（大量视频走这条路）
  └─ 命中 → 第 2 段
第 2 段 全扫：48 帧（间隔按总时长均分）
```

- 探针判定：排除"既靠边又很小"的行（水印/台标特征），其余（居中/大字）都算有内容
- 抽帧统一缩到 720 宽（1080×1920 → 720×1280，OCR 快数倍）
- 帧数可用 `TRANSCRIPT_FRAME_OCR_PROBE` 调整（默认 8）

### 7.2 实测（4:13 抖音视频，带大量画面标注）

| 场景 | 结果 |
|---|---|
| **有画面文字** | 整条任务 **49 秒**（其中画面 OCR 约 30 秒：探针 8 + 全扫 48 帧 → 94 条） |
| **没有画面文字**（合成无字视频） | 探针 8 帧 → **2.8 秒**返回，`skipped=True`，不跑全扫 |
| 快手短视频（54 秒，带字） | 整条任务 **56 秒**（探针 8 + 全扫 36 帧 → 17 条 / 75 字） |

> 说明：早前记录的"画面 OCR 2 分 51 秒 / 整条 3.5 分钟"是在机器负载波动时测的；
> 同一实现复测为约 30 秒。现在**有字幕的视频整条也在 1 分钟内**，没字幕的视频只需几秒。

## 8. 测试

`pytest`：**155 项全过**。画面文字相关 20 项，覆盖：
- 抖音/快手通道必须执行 OCR；显式关闭时跳过
- 本地源不加 `-headers`、http 源加 Referer；抽帧缩放参数
- 探针→全扫的两段式（间隔分别按 8 帧 / 48 帧均分）
- 探针命中判定（角落小字=水印不算、居中大字算）
