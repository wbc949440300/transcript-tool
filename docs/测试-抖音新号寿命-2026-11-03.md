# 抖音新号连通性测试记录

> 日期：2026-11-03
> 目的：验证"抖音被风控"到底是被标记的账号问题，还是工具/网络问题

## 测试条件

| 项 | 值 |
|---|---|
| 账号 | `cookies/douyin/account_1.txt`（**新登录的号**） |
| profile | `cookies/_browser_profile_douyin_account_1`（全新干净） |
| 出口 | `http://127.0.0.1:7890`（Clash，与直连 IP 不同） |
| Cookie 模式 | `always`（让新号真正被使用） |
| 冷却闸门 | 关闭（`TRANSCRIPT_DOUYIN_COOLDOWN=0`） |
| 样本 | 2 条视频轮流（历史里仅有的 2 个抖音链接） |
| 间隔 | 每次 3 秒 |

## 结论

1. **旧账号是被标记的元凶。** 同样的网络、同样的工具、同样的 Clash 出口，
   换成新号后连跑 12 条零失败，说明"跑几条就被风控"**不是工具、不是 IP、不是浏览器**。
2. **同一批视频反复抓也没问题。** 12 次只用了 2 条视频轮流，抖音没有因此拦截。
3. **号池路线可行。** 单号至少能连续抓 12 条不触发验证码，
   接近申报口径的"单号安全日量 30 条"。

## 复测注意

- **登录窗口必须先关掉**：`login_cookie.py` 弹出的浏览器会锁住 profile，
  抓取端用同一个 profile 会启动失败（报 `Target page, context or browser has been closed`）。
  登录态已保存到 cookie 文件，关窗口不影响。
- 本次测试消耗了该号当天的 12 次额度，别再对同一个号追加测试。

## 2026-11-04 复评：结论 3「号池路线可行」需要修正

本文的测试方法本身没问题，但它只对照了「带新号」与「带旧号」，**没有对照「匿名」**，因此结论 3（号池路线可行）被后来的实测部分推翻：

| 本文结论 | 复评 |
|---|---|
| 1. 旧账号是被标记的元凶（同样的网络/工具/浏览器/出口，换新号 12/12 成功） | **成立**，仍然是解释「带号就要求验证」的最佳证据 |
| 2. 同一批视频反复抓也没问题 | **成立**（2026-11-04 又一次用同两条链接复测通过） |
| 3. 号池路线可行，单号能连抓 12 条≈安全日量 30 条 | **不必要**：2026-11-04 实测匿名就能取详情、图集、一级评论、热榜、分享链接，`cookies/douyin/` 现在是 0 个账号。号池只对「关键词搜索」有意义 |

补充事实（2026-11-04 09:19）：`/note/7642351924520437093` 10.3 s（`images=1`）、`/video/7671473405354953209` 10.1 s（`duration=188867ms`），全程无 cookie。10 秒一档的耗时来自 profile 被标记后改走干净上下文（见 `cookies/.douyin_profile_polluted.json` 里 2026-11-03 08:38 那条），不是接口变慢。
