## 3. 发现的问题

### 3.1 已复现的真问题：小红书错误提示被降级（建议修）

**现象**：小红书笔记取不到时，页面/历史里显示

> 该内容已删除或存在地区限制，无法提取。

**而真正有用的提示只写进了 `app.log`**：

> 笔记无法访问：链接可能缺少 xsec_token 或笔记已删除/受限。**请在小红书 App 里重新「分享 → 复制链接」后再试。**

**原因**（`app/extractor.py:914 _humanize_error`）：它把异常文案"翻译成人话"时，
最后那条 `"已删除" / "地区" / deleted / geo-restrict` 规则是**无条件匹配**的，
而小红书模块自己给出的提示里正好含"笔记**已删除**/受限"——于是被人话化的消息**再次**被改写成通用文案。

**一行复现**：

```
python -c "from app.extractor import _humanize_error as h; \
print(h(RuntimeError('笔记无法访问：链接可能缺少 xsec_token 或笔记已删除/受限。请在小红书 App 里重新分享→复制链接后再试。'),'小红书'))"
# 输出：该内容已删除或存在地区限制，无法提取。
```

修法建议（任选）：把"已是人话"的消息原样返回（例如含 `xsec_token` 或前缀匹配"笔记无法访问"时直接 return）；或把小红书这条规则提到"已删除/地区"规则**之前**。

### 3.2 接口一致性（轻微，不影响本机页面）

| 项 | 说明 |
|---|---|
| `/history/list`、`/history/detail` 返回 **snake_case** 原始列名（`task_id`/`text_content`/`webpage_url`） | 其它接口一律 camelCase，外部接入（Halo/脚本）容易踩 |
| `/transcript/image/ocr/doTask` 失败时 **HTTP 200 + body.code=500** | 其它接口用 HTTP 4xx/5xx |
| `/history/delete` 对不存在的 id 返回 **HTTP 200** + "记录不存在" | 其它接口 404；删除幂等本身没问题，只是状态码不统一 |

### 3.4 清理缺口

- **`tmp_uploads/` 没有启动清理**：任务被中断/进程重启时留下的上传副本不会有人管。
  当前就有一个 `tmp_uploads/7522190913787937286.wav`（320KB，15:01 的遗留）。
  正常跑完的任务会自动删（`file_transcribe.py` 的 `finally` 已验证）；`tasks/` 有 `sweep_orphan_task_files`，`tmp_uploads/` 没有对应清理。
- `F:\文案提取工具\wx_downloads\processed\` 有 **9 个视频号原片共 270MB**（按天清理默认关 `TRANSCRIPT_WATCH_KEEP_DAYS=0`）。
- 监听目录的用量统计把状态文件 `.transcript_watch_state.json` 也算成"待处理文件"（`inboxFiles=1`）。

### 3.5 统计口径 / 通知口径

- **空结果任务标 SUCCESS**：没有识别到口播时状态是 SUCCESS，`errorMessage` 记"没有识别到口播内容"（历史列表会把它显示出来，UI 不算误导）。
  但**失败率统计与浸泡报告的"失败轮 0"不含这类空结果**，数字偏乐观。
- **任务完成只弹桌面气泡，不会推微信**：ServerChan 只用于**告警**（`app/alerts.py:401` 是唯一调用点）。
  交接文档"通知策略"那行容易让人以为视频跑完也会推微信——实际不会。
