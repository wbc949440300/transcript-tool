# 扩展点与二次开发指南

> 目的：以后要加/改「代理池」「账号池」「并发策略」时，**改哪里、按什么约定改**。
> 原则：下面列出的函数是**稳定接口**（签名不要动，要扩就加参数带默认值），其余内部实现随便改。

---

## 1. 代理：策略面就三个函数（`app/utils.py`）

| 函数 | 语义 | 你会想改它的场景 |
|---|---|---|
| `proxy_pool(platform) -> list[str]` | 这个平台**能用哪些出口**。优先级：`TRANSCRIPT_PROXY_POOL_<平台>` > `TRANSCRIPT_PROXY_POOL` > 单条 `TRANSCRIPT_PROXY_<平台>` / `TRANSCRIPT_PROXY` | 想从"环境变量写死"升级成"从 API 拉列表/按城市分池/按号段分池" |
| `proxy_for(platform, key="") -> str \| None` | **挑哪一条**。`key` 非空 → 按 `_stable_hash(key)` 稳定绑定（同一个号永远同一条）；`key` 为空 → 轮询摊销 | 想改成"按延迟优先 / 按剩余流量 / 按城市就近" |
| `pick_proxy_available(platform, key="", tries=4) -> (proxy, egress)` | **跳过正在冷却的出口**，返回 (代理, 出口标识) | 想加"出口失败率超过 X% 就临时移出池子" |

配套：
- `egress_of(proxy)` / `egress_id(platform, key)`：出口标识，**冷却与预算都按它隔离**，别绕过
- `mask_proxy(url)`：展示用脱敏，日志/接口输出一律用它
- `proxy_check(platform)` / `proxy_checks()`：出口自检（返回 403/412 也算通），另有端点 `GET /prod-api/proxy/check`

调用约定（新增抓取代码时照抄）：
```python
from .utils import pick_proxy_available, http_opener, platform_cooldown_remaining

px, eg = pick_proxy_available("douyin", key=account_key(ck) or "anon")
if platform_cooldown_remaining("douyin", egress=eg) > 0:
    raise RuntimeError("该出口冷却中…")
with http_opener("douyin", proxy=px).open(req, timeout=20) as resp:   # ← 一定要把 px 传下去
    ...
```

## 2. 账号池：也是三个函数（`app/utils.py`）

| 函数 | 语义 | 你会想改的场景 |
|---|---|---|
| `pick_account(platform) -> str \| None` | **挑哪个号**：跳过冷却 → 今天用得最少 → 成功率最高；选中即记一次用量 | 想加"每号每日上限""按内容类型分配号" |
| `record_account_result(cookie_file, ok, platform="", reason="")` | 记一次成功/失败（健康度数据源） | 想加"失败原因归类统计" |
| `account_pool_snapshot(platform) -> list[dict]` | 页面展示用快照 | 想加"近 7 天成功率""上次使用时间" |

约定：
- 号文件路径：`cookies/<平台>/account_N.txt`（Netscape 格式），单号回退 `cookies/<平台>.txt`
- 命名必须与 `login_cookie.py --account account_N`、`douyin._profile_name_for()` 保持一致
  （同一个号 → 同一个浏览器 profile 目录）
- 落盘状态：`cookies/.accounts.json`（用量/健康度）、`cookies/.cooldown.json`（平台+出口+账号冷却）
- 解析要用 `utils.load_netscape_cookies()` / `cookies_header_for()`，**不要自己写解析**

**每账号每日上限**：`TRANSCRIPT_ACCOUNT_DAILY_MAX`（默认 30，0=不限）。
达到上限的号当天不再被挑中；**全部到上限时临时放宽并告警**（10 分钟最多报一次），
不会让任务停摆。快照 `account_pool_snapshot()` 里带 `dailyMax` / `capped` 字段供页面展示。

**强制指定账号**：`TRANSCRIPT_ACCOUNT_FORCE=<cookie 文件路径>`，
`pick_account()` 会直接返回它——巡检脚本（`scripts/account_check.py`）靠这个把请求
固定到某个号上；做单号调试时也可以用。

**批量导入**：`scripts/import_accounts.py <平台> <cookie 文件或目录>`，
支持 Netscape 文件与 `name=value; …` 串，自动编号到下一个空位，校验域名与关键字段后写入池子。

## 3. 加一个平台：只改 `app/platforms.py`

```python
PlatformAdapter(
    key="newsite", label="某站", hosts=("newsite.com",),
    run_kind="generic",              # 或自定义通道名 + 在 extractor._run_task 里分发
    needs_login=True, supports_images=False,
    frame_ocr_default=False,        # 没有平台字幕的平台设 True
    cooldown_base=900, daily_budget=100,
)
```
抓取实现放独立模块（`app/<平台>.py`），只暴露 `fetch_<平台>(url, timeout, use_cookie) -> dict`。

## 4. 并发：现状与"以后要改哪里"

### 现在真实的串行点（高并发时都会成为瓶颈）

| # | 串行点 | 位置 | 影响 |
|---|---|---|---|
| 1 | **全局 ASR 单锁** | `extractor._WHISPER_LOCK`（文件任务共用同一把） | 所有转写（链接/上传/监听）严格串行；GPU 6GB 只能跑一个模型 |
| 2 | 每平台 1 个并发槽 | `scheduler` 平台队列 + `platform_serialized()` | 同平台串行（**有意为之**，防风控）；跨平台可并行 |
| 3 | OCR 引擎单例 | `ocr._get_engine()` | 图片 OCR 与画面 OCR 共享一个实例，**RapidOCR 线程安全未验证** |
| 4 | whisper 模型缓存 | `extractor._MODEL_CACHE`（默认 2 个） | 换模型会挤显存 |
| 5 | SQLite 单连接 + 线程锁 | `history._HistoryStore` | 写入串行；**多进程会冲突** |
| 5 | 浏览器 profile 独占 | `browser.open_profile()` | 同一 profile 不能被两个实例同时打开 → **同账号串行**（不同账号可并行） |
| 6 | 状态文件 | `.accounts.json` / `.cooldown.json` / `.budget.json` | 进程内锁安全，**多进程不安全** |
| 7 | 归档重名 | `archive._unique_path()` | exists→write 有竞态，高并发可能撞名 |

### 要上高并发时建议的改造顺序

1. **资源池化**：把"ASR 槽位 / OCR 槽位 / 平台出口槽位 / 浏览器 profile 槽位"抽象成可配置的并发池
   （`TRANSCRIPT_CONCURRENCY_ASR`、`_OCR`、`_<平台>`），每个功能声明它需要哪些资源；
   调度器按资源而不是按线程数排队
2. **长短任务分级**：链接提取/ASR 属长任务，导出/笔记/OCR 属短任务 → 短任务独立队列，避免被长任务堵死
3. **多进程/多实例**：一台机器跑不动时，按平台分进程（抖音一个进程、快手一个进程）；
   此时 §4 表格里的 5/6 项要换成真正的跨进程锁，或把状态集中到一个写入者
4. **观测**：每资源的排队时长、并发度、失败率（现有 `/risk/status` 扩展）

> 现在**不要**提前做这些：单机中等量级下，链路 1~2 反而是保护（避免把平台打爆、避免显存 OOM）。

## 5. 测试约定（加代码时照这个来）

- 全部用 `tests/` 下的 pytest；`conftest.py` 已把所有状态目录指到临时目录（**绝不碰真实 cookies/历史库**）
- 需要外部网络的一律打桩：假 `http_opener`、假 `yt_dlp.YoutubeDL`、假 `_run_task`
- 新增能力时同步加 3 类用例：正常路径、边界（空/坏数据）、拒绝路径（该拦的必须拦住）
- 运行：`F:\python\python.exe -m pytest`（约 230 项、30 秒内）
